# RecruitAI（简历筛查）深度调查智能体升级方案

## 一、 项目背景与升级初衷

### 1.1 现状与瓶颈
当前简历筛查系统（RecruitAI）采用的是**单步工作流（Workflow）**架构：
1. 文档解析（PDF/Word）；
2. 正则规则卡控学历、院校、工龄硬门槛；
3. 一次性调用大模型生成分数、五维雷达图与 3 道标准面试题。

**核心痛点**：
- **无法识破履历包装**：候选人若在简历中声称“主导微前端架构”、“负责千万级高并发系统”，现有单次 Prompt 容易被华丽辞藻误导，给出虚高评分；
- **外链资产形同虚设**：简历附带的 GitHub 仓库、技术博客或论文链接，系统无法主动探查其实际技术含金量（是否仅为 Fork 模板、近一年是否有真实提交）；
- **时间线漏洞缺乏交叉比对**：对于“毕业 2 年却有 4 段长期全职经历”、“学历年限与资历倒挂”等造假隐患无法自动识别；
- **面试题千篇一律**：生成的面试题偏八股文，无法针对候选人项目的可疑漏洞进行靶向“测谎”。

### 1.2 升级目标
将当前的单步工作流升级为**「漏斗式两段复合智能体（Two-Stage Funnel Compound Agent）」**：
- **前置 Workflow 守门员**：保留毫秒级正则硬规则，秒级剔除不合格简历，维持系统高吞吐与低成本；
- **后置 ReAct 深度调查 Agent**：对通过粗筛的高潜候选人，启动具备“**自主规划、工具调用、时间线测谎、外部探查、自我反思**”能力的资深招聘猎头 Agent。

## 三、 Agent 核心行动层工具箱 (Agent Tool Registry)

在 `app/core/agent_tools.py` 中注册 4 个供大模型自主调用的专用工具：

### 1. `timeline_cross_auditor`（履历时间线自洽性测谎工具）
- **职责**：提取候选人受教育时间、各段工作履历起止时间，进行数学交叉比对；
- **检测重点**：
  - 是否存在时间严重重叠（如同时在两家全职公司任职）；
  - 毕业年限与所声称的职级是否严重脱节（如工龄 1.5 年声称担任总架构师）；
  - 经历中是否有未说明的空档期（Gap Year > 1 年）。

### 2. `external_asset_probe`（开源代码与外部技术资产探查工具）
- **职责**：当简历中出现 GitHub/GitLab 链接、个人技术博客、在线作品集时，Agent 自主决定调用；
- **检测重点**：
  - 探查 GitHub 仓库：代码行数、语言分布、Commit 活跃度、是否为简单 Fork；
  - 识别真伪：判断项目是真实的自研项目还是复制粘贴的教学 Demo。

### 3. `project_substance_evaluator`（项目含金量与划水判定器）
- **职责**：针对候选人声称的“核心高并发/架构重构”进行深度关键词语义下钻；
- **检测重点**：
  - 检查项目描述是否充斥“负责推进、协同配合、参与开发”等虚词，缺乏具体的量化技术指标（如 QPS 从 500 提升至 5000、P99 降低 70%）；
  - 剥离夸大辞藻，还原候选人的真实贡献度。

### 4. `killer_question_generator`（靶向高难度测谎题生成器）
- **职责**：结合前述工具发现的可疑点、断层或核心项目亮点，出具 3 道不可在网上搜到标准答案的攻防型面试题；
- **示例**：
  - *“候选人声称在 X 项目中使用 Raft 协议解决多节点数据一致性。请重点追问：在网络分区发生时，其集群如何防止脑裂（Split-brain），具体的选举超时时间（Election Timeout）参数如何调优？”*

## 四、 ReAct 状态机主循环实现规范

参考《合同审查》项目已验证的稳定状态机范式，在 `app/core/recruitment_agent.py` 中实现闭环调度：

```python

    """
    资深技术招聘尽调 Agent（感知 → 规划 → 行动 → 反思）
    """
    def __init__(self, llm_client):
        self.llm = llm_client
        self.max_rounds = 3       # 单候选人最大工具调用轮次（预算硬约束）
        self.timeout_seconds = 45 # 超时熔断保护

    async def run_deep_screening(self, resume_text: str, job: dict) -> dict:
        # 1. Perceive: 提取关键线索与可疑点
        # 2. Plan: 决定是否需要调用外部探查或时间线校验工具
        # 3. Act: 执行 <tool_call> 并回灌 <tool_result>
        # 4. Reflect: 综合工具取证结果，反思推翻虚假高分，得出真实评级
        ...
```

### 预算硬约束（避免死循环与耗时失控）：
1. **工具轮次上限**：每个候选人最多调用 3 轮工具，达到上限强制收敛并总结；
2. **熔断兜底**：任何网络外链抓取超时（>3秒）立即静默降级，不阻塞整体流程；
3. **成本控制**：通过粗筛的候选人平均调用 Token 限制在 3000 Tokens 以内。

### 5.2 前端 Stitch 抽屉升级
在现有的 `static/index.html` 右侧 A4 简历抽屉中：
1. **新增「AI 尽调取证轨迹」折叠面板**：展示 Agent 思考、查工具与反思纠偏的全过程；
2. **新增「打假预警红黄标签」**：如果发现履历包装，在头像下方亮起醒目的红色警戒徽章；
3. **靶向面试题专栏**：将面试题明确标注为“【履历验真题】”、“【架构深度题】”。

## 七、 总结

通过本次升级，RecruitAI 将彻底摆脱“单次填空工作流”的局限：
- **粗筛阶段**：依旧快如闪电（保持 Workflow 的高吞吐与零成本）；
- **精筛阶段**：犹如一位配备了放大镜和专业背景调查工具的**资深技术猎头（真正的 Agent）**，具备侦破履历水分与主动求证的真正智能！
