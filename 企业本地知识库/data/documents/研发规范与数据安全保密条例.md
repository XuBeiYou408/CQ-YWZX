# 企业信息技术研发规范与数据安全保密条例

## 第一章 代码管理与工程规范
1.1 Git 代码分支规范：
   - 主干分支（master/main）：仅用于部署生产环境，必须打 tag 标签，严禁直接 push，仅限通过 Pull Request 经 Code Review 双人合并。
   - 开发分支（develop）：日常集成主分支。
   - 功能分支（feature/*）：各迭代需求独立分支，命名规范：feature/需求编号_简短描述。
1.2 代码提交规范：严格遵循 Conventional Commits 协议，如 feat:、fix:、docs:、refactor:、test:、chore:。
1.3 单元测试覆盖率：核心业务逻辑模块（订单、支付、资产计算）单元测试覆盖率不得低于 80%，CI 流水线自动化测试未通过禁止合并分支。

## 第二章 数据安全与脱敏要求
2.1 敏感信息定义：
   - 个人隐私数据：身份证号、手机号、家庭住址、生物识别特征；
   - 商业机密：财务流水、客户合同协议、系统架构拓扑图、内部接口 API Key。
2.2 脱敏规范：
   - 日志打印与测试环境：严禁将明文敏感信息写入 log 文件；测试环境数据库必须通过自动化脱敏工具做掩码替换（手机号掩码 138****0000）。
   - 源码保密：严禁将任何私有 API Key、数据库明文密码、私钥硬编码进代码仓库。

## 第三章 生产运维与权限管控
3.1 堡垒机管理：生产服务器禁止开放外网直接 SSH，必须通过企业 VPN + 堡垒机双因子认证（2FA）登录。
3.2 数据库变更：所有生产 DDL 与 DML 操作必须提交工单，经 DBA 审核并在业务低峰期执行，禁止未经验证的全表 update/delete 操作。
3.3 离职交接：员工离职当日必须完成 Gitlab 账号、VPN 证书、云平台控制台访问权限的实时注销与代码资产移交。
